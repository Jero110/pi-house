# Fleet chat on macOS

Open the workspace, type a request and press Enter. Codex and the first configured project are selected initially. Options changes the agent or project for a new chat. A chat stays on its owning Mac. The transcript labels work by machine and agent. The Artifacts panel opens text and supported image previews and downloads original files. Older versions stay attached to the chat.

Each host clones the committed project into its own private checkout per chat. The optional planning Mac receives recent conversation text and returns a short suggestion from a disposable workspace. The primary agent receives the suggestion and works in the chat's checkout. Source code, login files and SSH agents are never forwarded to the planner by the transport. A failed planner connection is recorded in the timeline. The primary can still complete the turn.

## Configure a Mac

Install the checkout with Node 26.11.1 or newer and the pinned dependencies (`npm ci --ignore-scripts`). Install Tailscale for macOS and enable HTTPS certificates for your tailnet. Install and sign in to a native Codex CLI supporting named filesystem permissions. Run the worker's doctor before allowing tasks. Install Claude Code if using Claude.

Keep this host configuration outside all project repositories. Use the DNS name reported by `tailscale status --json`, the exact Tailscale login, canonical absolute paths, and an unoccupied port. The project directory must be a trusted Git working tree. The private state directory must have mode 0700.

```json
{
  "host": "Primary Mac",
  "origin": "https://primary.example-tailnet.ts.net:8443",
  "login": "owner@example.org",
  "stateDir": "/Users/dev/.pihouse/fleet-state",
  "projects": { "app": "/Users/dev/Developer/app" },
  "peers": [{ "label": "Second Mac", "url": "https://second.example-tailnet.ts.net:8443" }]
}
```

```sh
node packages/pihouse/src/cli.ts fleet serve /absolute/path/host.json
# From another terminal on this host:
node packages/pihouse/src/cli.ts fleet open /absolute/path/host.json
```

For another device, open the host's HTTPS URL and enter a code generated by `pih fleet pair /absolute/path/host.json` on the host. Codes expire after five minutes and are consumed once. Browser sessions expire after eight hours or when the host service restarts. The listener binds only to its actual tailnet addresses. The backend obtains the owner of the incoming connection with Tailscale WhoIs and checks that identity on every route, including asset downloads. It rejects tagged nodes. No reverse proxy, Funnel or public port forwarding is required. On macOS a user LaunchAgent can run the serve command after login; supply an absolute Node path and a PATH containing Git and the native CLIs.

## Add a planning Mac

Add a private `planner` object on the primary host. Its `label` appears on planner messages. Use a dedicated SSH identity and a known-hosts file with the verified host key. Only the operator may change these files or the server config.

```json
{
  "label": "Second Mac",
  "host": "dev@second.example-tailnet.ts.net",
  "identityFile": "/Users/dev/.pihouse/planner-key",
  "knownHostsFile": "/Users/dev/.pihouse/planner-known-hosts",
  "node": "/absolute/path/to/node",
  "entry": "/absolute/path/to/pi-house/packages/pihouse/src/fleet-planner.ts"
}
```

On the planning Mac, install the same revision and complete native Codex sign-in. Restrict the dedicated public key in that user's authorized_keys to the primary's tailnet IP and this exact command:

```text
from="100.64.0.1",restrict,command="/absolute/path/to/node /absolute/path/to/pi-house/packages/pihouse/src/fleet-planner.ts --worker" ssh-ed25519 PUBLIC_KEY
```

## Execution and security boundaries

- One turn writes a checkout at a time. Chats, messages, events and artifact snapshots are persisted in the host's SQLite store. Hosts record unfinished work as interrupted after a restart. They do not automatically replay a potentially non-idempotent edit.
- The host keeps its active tasks running across browser disconnects. It must be awake. The default turn deadline is two hours, configurable with `turnTimeoutMs` up to 24 hours. Full process isolation from the operating system administrator is outside this design.
- Work inside the chat checkout remains available at `stateDir/checkouts/<chat ID>`. The operator reviews and promotes code explicitly. Deliver files in the checkout's flat `artifacts/` directory. The host snapshots changed regular files after a successful turn. It bounds file and storage sizes and rejects unsafe links. Active document types are download-only.
- See [Native Mac fleet workers](fleet-sandbox.md) for each backend’s authentication, available tools and model restrictions. Run `node packages/pihouse/src/fleet-sandbox.ts doctor pi`, replacing `pi` with `codex` or `claude`, on each worker. A passing doctor checks local enforcement and CLI startup. A successful provider turn also requires a working subscription and an available model.
- Codex uses its native ChatGPT subscription login and tool permissions. Pi uses its own operator-provisioned ChatGPT login (`fleet-sandbox.ts login pi`). Claude's existing claude.ai login supports a clearly labeled chat-only session. Dedicated file-tool mode is provisioned separately with `fleet-sandbox.ts login claude`. Never paste subscription tokens into a chat or commit a host profile.
- The trust boundary includes the macOS user, installed native binaries, Tailscale and selected provider. A compromised Mac or administrator can control its service. The app sends the prompt and any project context selected by the agent to its provider under that account. Untrusted checkouts should not contain secrets.
